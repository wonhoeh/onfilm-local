# OnFilm Local

배우 한 명이 PC에서 포트폴리오를 만드는 Electron + Spring Boot 앱. 초기 화면은 기존 OnFilm의 프로필 편집 스타일을 재사용한 **프로필 입력 전용 화면**이다. 이름·출생일·출생지·소개글·SNS·태그를 입력한다.

기존 OnFilm 서버형 프로젝트와 독립적이다. MySQL·Kafka·Docker·별도 Worker·AWS 계정·DB 비밀번호 설정은 필요 없다. 기존 데이터와 `.env`를 복사하지 않는다.

## 백엔드 패키지 구조

`backend/src/main/java/com/onfilm/local` 아래에서 기능별로 분류한다. 테스트도 같은 기능 패키지에 둔다.

```text
com.onfilm.local
├── OnfilmLocalApplication       앱 시작점
├── config                      DB 등 인프라 설정
├── security                    로컬 요청 접근 제한
├── profile                     프로필·SNS·태그·대표 사진
├── gallery                     갤러리 사진·순서 관리
├── filmography                 작품 정보·섬네일 연결
└── media
    ├── image                   공통 이미지 정규화·업로드 오류 처리
    ├── video                   영상 복사·저장·작품 연결
    └── encoding                로컬 FFmpeg 인코딩·작업 상태·HLS 제공
```

현재 기능 단위 패키지 분리이며, 모든 Controller의 DB 접근을 Service/Repository 계층으로 추출한 것은 아니다. API 주소·DB 마이그레이션·저장 경로·화면 동작은 그대로 유지한다.

## 개발 실행 (macOS)

필요: Java 21, Node.js 22.12 이상(LTS 권장). 첫 빌드와 npm 설치에는 인터넷이 필요하다. 완성된 Windows 설치 파일이나 Java 런타임 번들링은 아직 없다.

```sh
cd backend
./gradlew bootJar
cd ../desktop
npm ci
npm start
```

Windows 개발 환경에서는 `gradlew.bat bootJar`를 사용한다. 실제 Windows 실행은 아직 검증하지 않았다.

아이콘 설치 전 개발 단계라 `npm start`로 실행한다. 앱이 Java API와 파일형 H2 DB를 함께 시작하고, 준비가 끝나면 편집 창을 연다. API를 IntelliJ에서 따로 켜지 않는다. 종료 시 앱이 시작한 API만 종료하며 DB 파일은 보존한다.

이름(필수, 최대 60자)·소개(최대 120자)를 입력하고 **이 PC에 저장**을 누른다. 앱을 종료하고 다시 실행해 값이 유지되는지 확인한다. 입력 중인 내용은 자동 저장하지 않으며, 미저장 변경이 있으면 종료 확인을 표시한다.

### 인코딩 개발 설정

현재 FFmpeg·ffprobe는 별도 설치가 필요하다. PATH에서 실행할 수 있으면 추가 설정 없이 사용한다. 경로를 지정하려면 `npm start` 전에 `ONFILM_FFMPEG`와 `ONFILM_FFPROBE` 환경변수에 실행 파일의 절대 경로를 설정한다. Windows 실행 파일 동봉은 아직 하지 않았다.

필모그래피 편집에서 영상을 저장한 후 **인코딩 시작**을 누른다. 앱을 열어 두면 한 개씩 최대 720p HLS로 변환하며 대기/진행/완료/실패 상태를 표시한다. 실패·중단 작업은 **인코딩 재시도**로 다시 시작한다. 중간 프레임부터 이어받는 방식은 아니다. 원본과 실패한 결과는 보관되므로 디스크 공간에 유의한다.

완료 후 **영상 보기** 또는 프로필의 **작품 카드**를 누르면 기존 OnFilm 구성의 로컬 재생 화면이 열린다. 재생/일시정지, 타임라인 이동, 10초 이동, 볼륨, 배속, 전체 화면을 제공한다. HLS.js 1.7.3은 앱에 포함되어 CDN/인터넷 연결이 필요 없다. 영상이 없거나 읽기에 실패하면 안내와 **다시 읽기**를 표시한다. 연결 해제/교체된 이전 영상은 새 요청으로 재생할 수 없다. 상세: `docs/decisions/009-local-playback.md`.

재생 화면은 선택한 영상을 자동재생한다. 단축키: **Space/K** 재생·정지, **←/→** 5초 이동, **↑/↓** 볼륨, **F** 전체 화면, **M** 음소거. 재생 바에 커서를 올리면 해당 시점의 작은 영상과 시간이 표시되며 본 영상의 재생 위치는 바뀌지 않는다.

### 실행 중 빌드 주의

실행 중인 앱이 사용하는 JAR를 다시 빌드하면 클래스 로딩 오류가 날 수 있다. 일반 `bootJar` 빌드는 **앱을 완전히 종료한 뒤** 실행한다. 앱을 켜 둔 채 검증하려면 다음처럼 격리된 빌드를 사용한다.

```sh
cd backend
./gradlew -PverificationBuild check bootJar
cd ../desktop
ONFILM_TEST_JAR="$PWD/../backend/build-verification/libs/onfilm-local.jar" npm run test:e2e
```

이 검증 빌드는 일반 `npm start`가 사용하는 JAR를 갱신하지 않는다. 최신 기능을 직접 실행할 때는 앱 종료 → 일반 `./gradlew bootJar` → `npm start` 순서로 진행한다.

## 공개본 만들기

프로필의 톱니바퀴 메뉴 → **공개본 만들기 · 미리보기** → 공개 정보 포함 확인 → **새 공개본 만들기**. 결과 목록에 파일 수와 총 MB를 표시한다. 현재 프로필의 생년월일·출생지·SNS·사진 등도 포함되므로 먼저 확인한다.

결과물은 앱 데이터 폴더의 `exports/<생성 ID>/site`에 저장된다. 이 `site` 폴더만 정적 호스팅에 배치할 수 있다. 아직 외부 게시나 비용 발생은 없으며 **미리보기**로 앱 안에서 확인한다. HTML 파일 직접 더블클릭은 지원하지 않는다.

로컬을 수정해도 이전 공개본은 바뀌지 않는다. 다시 만들면 새 복사본이 생기므로 디스크 공간을 사용한다. 미완료 인코딩은 먼저 완료해야 하며 원본 영상·DB는 내보내지 않는다. 완료 공개본은 ZIP 저장·결과 폴더 열기·휴지통 이동을 지원한다. 온라인 업데이트는 후속 단계. [설계와 제한](docs/decisions/010-static-portfolio-export.md).

같은 화면의 **사용량 확인**은 DB·미디어·공개본(앱 내부 ZIP 캐시와 부분 파일 포함)의 논리적 파일 크기를 합산한다. 외부 백업·복원 전 보관 폴더·외부 ZIP·휴지통은 제외되며, 작업 중에는 값이 달라질 수 있다. **휴지통으로 이동**은 확인한 완료 공개본 하나만 정리한다. DB·원본 영상·백업·이미 게시된 사이트는 바뀌지 않는다. OS 휴지통을 비우기 전까지 복구할 수 있고 실제 여유 공간 확보에는 휴지통 비우기가 필요할 수 있다. 이동 실패 시 영구 삭제로 대체하지 않는다. 미완료 공개본이나 알 수 없는 파일/심볼릭 링크가 포함된 폴더는 이 기능으로 정리하지 않는다.

## 데이터 위치

기본값은 Electron의 `userData` 아래 `data/database/onfilm.mv.db`다.

- macOS: 일반적으로 `~/Library/Application Support/OnFilm Local/data/`
- Windows: 일반적으로 `%APPDATA%/OnFilm Local/data/`

정확한 상위 경로는 OS 설정에 따라 달라질 수 있다. 개발 시 `ONFILM_LOCAL_DATA_DIR`로 **새 전용 절대 경로**를 지정할 수 있다. 세미콜론·줄바꿈은 지원하지 않는다. 기존 프로젝트 DB나 미디어 경로를 지정하지 않는다.

```sh
ONFILM_LOCAL_DATA_DIR="/absolute/path/to/new-local-data" npm start
```

폴더를 바꾸면 다른 DB가 열리므로 기존 프로필이 사라진 것처럼 보일 수 있다. 데이터는 설치/소스 폴더와 분리한다. DB 파일을 실행 중에 복사하지 말고 앱의 백업·복원 화면을 사용한다. 첫 프로필 입력 화면에서도 백업·복원으로 이동할 수 있다.

## 선택 설정

Windows 설치형 앱을 위한 동봉 런타임 경로/누락 검사 기반을 준비했다. 아직 `.exe` 설치 파일과 실제 Windows 검증은 없으며 개발 실행 방법은 동일하다. [패키징 준비와 다음 단계](docs/windows-packaging.md).

Windows Java/FFmpeg 준비 자동화: backend에서 verificationBuild JAR를 만든 뒤 desktop에서 `npm run prepare:windows-runtime`, `npm run check:windows-runtime`을 실행한다. 기존 runtime 결과는 덮어쓰지 않는다. 다운로드 원본/실패 staging도 자동 삭제하지 않는다. 실제 확보한 runtime은 Git 제외 대상이며 Windows 이전 시 별도 복사 또는 재준비가 필요하다. 재배포 라이선스 검토와 Windows 실기기 검증은 별도다.

| 변수 | 기본값 | 의미 |
|---|---|---|
| `ONFILM_JAVA_PATH` | `java` | Java 21 실행 파일 절대 경로 지정 가능 |
| `ONFILM_LOCAL_PORT` | `18765` | loopback API 포트, 충돌 시 다른 프로세스를 종료하지 않음 |
| `ONFILM_LOCAL_DATA_DIR` | OS별 앱 데이터 경로/data | 사용자 데이터 위치 |

로그인 계정·JWT·Callback secret은 사용하지 않는다. Electron이 매 실행마다 무작위 로컬 접근 토큰을 생성한다. 일반 브라우저에서 localhost URL을 직접 열면 403으로 차단되는 것이 정상이다. 토큰을 URL/파일/로그에 저장하지 않는다.

## 검증

```sh
cd backend
./gradlew check bootJar
cd ../desktop
npm test
npm run test:e2e
```

E2E는 GUI 실행이 가능한 환경에서 실제 Electron + Java JAR를 사용한다. OS 임시 폴더에 별도 테스트 DB를 만들고 저장·프로세스 재시작·재조회·접근 제한을 검사한다. 진단용 임시 폴더 위치를 출력하며 실제 사용자 DB를 사용하지 않는다.

## 현재 범위와 제한

- 프로필 톱니바퀴 → **데이터 백업 · 복원**에서 DB·사진·작품·원본 영상·HLS를 폴더 형태로 백업/복원한다. 인코딩 완료 후 사용하며 작업 중 서버가 잠시 종료된다. 복원 전 데이터는 별도 보관한다. 백업은 암호화되지 않으며 공개본 ZIP과 다르다. 본인이 만든 백업만 선택하고 폴더 전체를 보관한다. 공개본·ZIP은 백업에서 제외한다. 중단 복구 기록이 있으면 데이터 보호를 위해 자동 시작을 차단한다. [상세 제한과 복구 정책](docs/decisions/011-local-backup-restore.md)을 확인한다.

- 프로필 편집의 **CONTACT ME**에는 이메일만 입력한다. 입력 후 저장하면 프로필과 새 공개본에 표시하며, 비우면 CONTACT ME 전체를 숨긴다. 공개 체크박스·공개 표시 문구·전화번호 입력은 없다. 기존 전화번호 DB 값은 보존하지만 API/새 공개본에는 포함하지 않는다. 이전 공개본/ZIP/게시된 사이트는 자동 갱신되지 않는다.

- 프로필 톱니바퀴 → **공개본 만들기 · 미리보기**에서 완료한 공개본을 **ZIP 저장**하거나 **결과 폴더 열기**로 확인할 수 있다. ZIP은 읽기 전용 페이지·이미지·완료 HLS만 포함한다. 기존 동명 파일은 덮어쓰지 않으므로 새 이름을 선택한다. 인터넷에 자동 게시하는 기능은 아직 아니다. ZIP 캐시와 이전 공개본은 자동 삭제하지 않는다. 자세한 제한은 [공개본 설계](docs/decisions/010-static-portfolio-export.md)를 참고한다.

- 기존 OnFilm의 `common.css`·`edit-profile.css`·`actor-detail.css`와 프로필 구성을 재사용한다. 사진 열·로그인 연동·서버 사용자별 URL 이동은 제외하고 로컬 저장 API로 연결했다.
- 첫 실행에는 프로필 입력 화면, 저장 후에는 프로필 조회 화면이 열린다. 이후 앱 실행도 저장된 이름이 있으면 조회 화면으로 시작한다. ‘프로필 편집’으로 수정하고 저장하면 조회 화면으로 돌아간다. 이름 이외의 필드를 비워도 저장할 수 있다.
- 조회 화면은 원본 OnFilm의 프로필 사진·SNS 아이콘·태그·FILMOGRAPHY·PHOTO·빈 게시물 버튼·톱니바퀴 메뉴 구성을 사용한다. 로컬 미리보기이며 온라인 공개본은 아니다. SNS 아이콘을 누르면 주소 복사 안내를 보여준다. 외부 브라우저 자동 열기는 아직 없다. 조회 실패 시 빈 프로필로 간주하지 않고 재시도 버튼을 표시한다.
- 대표 사진·갤러리·필모그래피는 초기 입력 화면에 표시하지 않는다. 프로필 저장 후 편집 화면에는 기존 OnFilm과 같은 왼쪽 대표 사진 영역이 표시된다. 클릭/파일 선택/드롭으로 추가·교체하고 확인 후 삭제한다. JPG/PNG 5MB 이하, 긴 변 2,048px 자동 축소. 사진은 즉시 저장되고 입력 중인 기본 정보는 유지된다. 실패 시 다시 읽기로 저장 여부를 확인한다. 기존 사진 데이터는 기본 프로필 저장으로 삭제하지 않는다.
- PHOTO의 ‘첫 사진 등록하기’ 또는 톱니바퀴 메뉴의 ‘사진 갤러리 편집’에서 별도 갤러리 편집 화면으로 이동한다. 기존 OnFilm의 `edit-gallery.css`·업로드 영역·카드 구성을 재사용한다. 파일 선택/드롭, 앞뒤 이동, 개별 삭제를 지원하며 변경은 즉시 저장된다. 원래 화면의 전체 비우기·공개 설정·드래그 정렬·일괄 저장은 이번 로컬 화면에 포함하지 않는다.
- FILMOGRAPHY의 ‘첫 작품 등록하기’ 또는 톱니바퀴의 필모그래피 편집에서 작품 정보를 관리한다. 기존 `edit-filmography.css`와 카드/입력 구성을 재사용한다. 제목·연도·런타임·관람연령·장르·참여 역할·배역을 입력하고, 위로/아래로 정렬하거나 삭제한 뒤 **저장**하면 한 번에 반영된다. 최대 50개. 장르는 쉼표로 구분한 직접 입력만 지원한다. 공개 설정, 드래그 정렬은 아직 없다. 랜딩페이지는 없다.
- 저장된 작품의 섬네일 영역에서 파일 선택/드롭으로 이미지를 추가·교체하거나 삭제한다. JPEG/PNG 5MB 이하, 긴 변 2,048px 자동 축소이며 원본은 변경하지 않는다. **섬네일은 즉시 저장**된다. 새 작품은 먼저 저장한 뒤 편집 화면으로 다시 들어온다. 미저장 작품 정보가 있으면 먼저 저장해야 섬네일을 바꿀 수 있다. 업로드 오류 후에는 다시 읽기로 실제 저장 상태를 확인한다. 프로필 카드에 저장된 섬네일을 표시하고 작품 삭제 시 섬네일도 함께 삭제한다.
- 사진은 최대 12장, 각 JPEG/PNG 5MB 이하이며 큰 사진은 비율을 유지해 긴 변 최대 2,048px로 자동 축소한다. 작은 사진은 확대하지 않으며 원본 파일과 이미 저장한 사진은 변경하지 않는다. 여러 장 업로드가 중간 실패하면 먼저 저장한 사진은 유지한다. 실패 후 ‘다시 읽기’로 실제 저장 상태를 확인해야 다시 변경할 수 있다. 완료 후 프로필 조회 화면에서 저장된 순서대로 사진이 표시된다.
- SNS는 최대 10개, HTTP(S) 주소만 저장한다(스킴 생략 시 https 추가). 태그는 최대 20개·각 30자이며 정규화 후 중복을 거부한다. SNS·태그·기본 정보는 같은 트랜잭션으로 저장한다.
- 저장된 작품의 **원본 영상 → 영상 선택**에서 MP4/MOV(최대 2GB)를 선택하거나 드롭한다. 파일을 앱 data 폴더의 `media/videos`로 복사하고 완료된 뒤 작품에 연결한다. 이름/크기/복사 전송 진행률을 표시하며, 교체·연결 해제를 지원한다. 미저장 작품 정보는 먼저 저장해야 한다. 원본은 수정하지 않으며 이 단계에서는 실제 영상 코덱 검증·인코딩·재생을 하지 않는다. 선두 ftyp 헤더가 없는 구형 MOV 등은 현재 거부한다.
- 영상 변경은 즉시 저장된다. 전송 실패나 응답 유실 시 다시 읽기로 저장 상태를 확인한다. 앱 중단 시 부분 복사본은 연결하지 않으며 원본을 다시 선택해야 한다. 교체·연결 해제·작품 삭제 및 실패로 남은 복사본은 복구를 위해 보관한다. 따라서 디스크 사용량이 늘 수 있고 정리 UI는 아직 없다. 자세한 정책은 [영상 저장 설계](docs/decisions/007-local-video-import.md)를 참고한다.
- EXIF 회전 보정은 아직 지원하지 않는다. 트레일러·스토리보드·온라인 게시 기능은 아직 없다. Windows 영상 재생 및 장시간·고해상도 영상은 별도 검증이 필요하다.
- H2 파일은 현재 암호화하지 않는다. 같은 OS 사용자 권한의 악성 프로그램으로부터 데이터를 보호하는 수단은 아니다.
- 정상 종료 시 자식 API를 정리한다. 프로세스 강제 종료·전원 차단·Windows 로그오프까지 정리를 보장하지 않는다.
- Windows 실제 실행·설치 파일·코드 서명·런타임 동봉·업데이트 및 강제 종료 후 자동 복구 UI는 남은 작업이다.
