# Cloudflare 게시

## 사용 순서

1. Cloudflare 연결 화면에서 R2·Pages 설정과 공개 주소 이름을 저장한다.
2. 프로필을 편집하고 영상 인코딩을 완료한다.
3. **공개본 만들기 → 새 공개본 만들기 → 미리보기**로 공개 정보를 확인한다.
4. 해당 공개본의 **게시**를 누르고 공개 주소·대상 Pages 프로젝트·미디어 용량을 확인한다.
5. `게시되었습니다` 안내 후 표시된 주소를 브라우저에서 연다. 예: `https://onfilm.co.kr/actor_01/`.

이 작업은 연결된 **Pages 프로젝트 전체**를 선택한 공개본으로 교체한다. 같은 프로젝트에 다른 사이트를 함께 보관하는 용도가 아니다. 로컬 편집 내용은 자동 게시되지 않는다. 수정 후 새 공개본을 만들어 게시해야 한다. ZIP을 수동 업로드할 필요는 없다.

## 무엇을 올리는가

- R2: 공개본에 포함된 대표 사진·갤러리·섬네일·인코딩된 원본/트레일러 HLS. 편집용 원본 영상은 제외한다.
- Pages: HTML·JS·CSS·아이콘·공개 프로필 JSON. `/<주소이름>/` 아래에 배치한다.
- 기존 상대경로와 재생 검증 코드는 유지한다. `/<주소이름>/media/*` 요청을 R2의 고정 콘텐츠 경로로 302 연결한다.
- `/`는 현재 공개 주소로 이동한다. 존재하지 않는 페이지는 404로 처리한다.
- API 키·로컬 DB·작업 기록·백업은 업로드하지 않는다. 원래 로컬 공개본과 ZIP도 변경하지 않는다.

## 진행·실패·재시도

- R2 업로드 진행률은 **완료한 파일의 바이트 합계** 기준이다. 큰 파일 하나를 전송하는 동안 퍼센트가 잠시 멈출 수 있다.
- 게시 중 앱 종료·백업/복원·공개본 휴지통 이동·연결 설정 변경을 막는다. `업로드·결과 대기 중단`으로 로컬 작업을 중단할 수 있다. 이미 접수된 Pages 배포는 계속 완료될 수 있다.
- 미디어 전체의 콘텐츠 해시로 R2 경로를 결정한다. 같은 미디어를 재게시하면 HEAD로 크기·해시 메타데이터를 확인하고 동일 파일은 PUT을 생략한다. 다른 내용의 파일은 덮어쓰지 않는다.
- 모든 R2 파일과 Pages 화면 업로드 후에만 운영 배포를 요청한다. Pages API의 production/deploy/success 응답을 확인해야 성공으로 표시한다.
- 마지막 성공 기록은 실패 시 지우지 않는다. 네트워크 장애로 상태를 확인하지 못한 경우 실패라고 단정하지 않고 **이전 배포 결과 확인**을 제공한다.
- Pages 접수 전에 고유한 요청 표식을 로컬에 기록한다. 배포 응답이 유실돼도 앱 재시작 후 표식으로 서버 기록을 찾아 결과를 확인하며 같은 요청을 무조건 재발행하지 않는다.
- 서버에서 배포 실패·거부가 확인되면 다시 게시할 수 있다. 접수 여부가 불명확하고 표식도 조회되지 않으면 새 배포를 차단한다. 이 드문 경우에는 Cloudflare 대시보드에서 진행 중인 배포 여부와 앱의 요청 표식을 확인해야 한다. 자동 강제 재배포·기록 초기화는 제공하지 않는다.
- 오류 메시지에는 원격 응답 본문이나 키를 노출하지 않는다.

## 비용과 남은 범위

R2 HEAD·PUT 및 저장 공간 사용은 발생한다. 무료 한도나 요금이 자동 보장되는 기능은 아니다. 이미 업로드한 미디어가 모두 동일하면 재사용하지만, 일부 미디어가 바뀌면 새 미디어 묶음이 생긴다. 기존·실패한 업로드 묶음은 이전 공개본을 깨뜨리지 않도록 자동 삭제하지 않는다. 따라서 저장 용량이 누적될 수 있다.

게시 종료, 오래된 R2 묶음 정리, 원격 사용량 표시, 필모그래피 전용 공개 페이지는 별도 후속 작업이다. 게시 완료는 Pages API 기준이며, 커스텀 도메인의 DNS·R2 CORS까지 확인했다는 뜻은 아니다. 실제 공개 주소에서 사진·트레일러·영상 탐색을 확인해야 한다. R2 CORS에 공개 사이트 출처를 허용해야 한다. `pages.dev` 주소로 확인하려면 해당 출처도 별도 허용해야 한다.

## 구현·검증

Electron main의 제한된 export-page IPC만 게시를 수행한다. renderer는 키나 임의 파일 경로를 전달할 수 없다. 암호화 연결 설정과 비밀값 없는 배포 영수증은 사용자 데이터 옆 `.connections` 폴더에 보관되어 프로필 백업에 포함되지 않는다. 복원된 프로필과 마지막 게시본은 서로 다를 수 있다.

Cloudflare의 [Direct Upload 배포 API](https://developers.cloudflare.com/api/resources/pages/subresources/projects/subresources/deployments/methods/create/), [공식 Wrangler 업로드 구현](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/pages/upload.ts), [파일 해시 규칙](https://github.com/cloudflare/workers-sdk/blob/wrangler%404.45.0/packages/wrangler/src/pages/hash.ts)을 기준으로 업로드 JWT, BLAKE3 콘텐츠 해시, manifest와 `_redirects`/`_headers` multipart를 구성한다. 외부 CLI나 추가 Node 설치 없이 앱의 런타임 의존성을 사용한다.

테스트는 가짜 자격증명·모의 Cloudflare 응답·임시 파일 H2 및 분리된 로컬 HTTP 미디어 서버만 사용한다. 실제 계정의 게시 결과와 Windows 설치 앱 동작은 별도로 검증해야 한다.
