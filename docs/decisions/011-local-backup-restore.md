# 로컬 백업·복원 (2026-09-30)

## 사용자 흐름

프로필 톱니바퀴 → **데이터 백업 · 복원**. 백업 만들기는 저장할 부모 폴더를, 복원은 `onfilm-backup-UUID` 폴더 자체를 선택한다. 복원은 OS 확인 창에서 재확인한다.

- 백업 폴더 전체를 함께 보관한다. 단일 ZIP이 아니며 암호화되지 않는다. 개인정보와 원본 영상이 있으므로 공개 호스팅에 업로드하지 않는다.
- 포함: 파일 H2 DB(프로필·사진·필모그래피·이메일·작업 기록), `media/videos`, `media/encoded`. 복구를 위해 미연결/부분 미디어도 함께 보관한다.
- 제외: 공개본/ZIP/로그/실행 프로그램/설정 및 실행 토큰. 공개본은 복원 후 다시 만든다. 이전 공개본은 복원 전 데이터 폴더에 남는다.
- 인코딩 RUNNING/QUEUED가 있으면 거부한다. 작업 전 서버 상태를 확인하고 자기 소유 API를 정상 종료한 뒤 복사한다. 강제 종료된 경우 백업/복원을 진행하지 않는다.
- 작업 중 창 닫기/화면 이동을 제한한다. OS 강제 종료/전원 차단을 막지는 못한다. 작업 중 퍼센트 표시/취소 기능은 아직 없다.

## 백업

선택한 폴더에 고유 `.partial` 폴더를 만들고 `data/database/onfilm.mv.db`, 미디어를 복사한다. 크기·SHA-256 목록과 생성 시각을 `onfilm-backup.json`에 기록한 뒤 완료 폴더로 rename한다. DB와 미디어의 심볼릭 링크는 허용하지 않는다. 앱 데이터 내부에 백업을 만들 수 없다. 완료 후 서버를 재시작한다.

파일 목록 최대 10만 개, 목록 JSON 최대 16MiB. 파일별 스트리밍 체크섬을 사용한다. 예상 공간+64MiB를 미리 확인하지만 실제 디스크 고갈/권한 오류는 여전히 발생할 수 있다. 실패 부분 폴더는 자동 삭제하지 않으며 복원 대상으로 거부한다.

## 복원

1. 백업 형식·허용 상대 경로·중복/심볼릭 링크·파일 수·바이트 수·모든 체크섬 검사.
2. 사용자 확인 및 인코딩 유휴 상태 확인, API 종료.
3. 데이터 폴더와 같은 부모 아래 고유 staging 폴더에 복사하며 체크섬 재검증.
4. `<dataDir>.restore-pending.json` 복구 기록을 fsync로 기록.
5. 기존 data를 `onfilm-before-restore-UUID`로 이동하고 staging을 data로 이동.
6. 동일 API를 재시작하여 H2/Flyway/애플리케이션 준비 확인. 성공하면 복구 기록 제거, 이전 데이터 보관.
7. 시작 실패 시 API를 종료하고 실패 데이터를 별도 폴더로 보관한 뒤 이전 data를 되돌린다. 기존 서버 재시작을 시도한다.

복원 중 종료되어 복구 기록이 남으면 다음 앱 시작을 차단한다. **자동으로 빈 DB를 생성하거나 폴더를 삭제하지 않는다.** 복구 기록에 있는 root/previous/stage/failed 경로를 보존한 상태로 진단 후 복구해야 한다. 현재 자동 중단 복구 UI는 없다. 전원 차단에 대한 모든 파일시스템의 내구성을 보장하지 않는다.

## 보안·제한

- Electron main에서만 파일 시스템/OS dialog를 사용한다. renderer는 create/restore 동작만 전달하며 임의 경로를 전달하지 않는다. 자기 창 main frame, 정확한 origin과 `/backup.html` 발신을 검사한다.
- 체크섬은 우발적 손상 검사이지 출처 인증이 아니다. **본인이 만든 신뢰할 수 있는 백업만 복원한다.** 임의의 H2 데이터 파일을 안전하게 샌드박싱하는 기능은 아니다.
- 아직 버전 간 복원 호환성/DB와 미디어의 모든 참조 무결성 검사를 보장하지 않는다. 같은 앱 버전 백업을 기준으로 사용한다. 이후 버전의 DB는 Flyway/시작 검증에서 거부될 수 있다.
- 앱은 1인/한 프로세스 사용을 전제로 한다. 다른 프로그램이 데이터 폴더를 직접 변경하거나 다른 API를 같은 데이터로 실행하는 것은 지원하지 않는다.
- 루트/홈 폴더 및 database/media/exports 외의 파일이 섞인 폴더는 앱 데이터 대상으로 거부한다. 지정된 앱 데이터 외의 사용자 폴더를 복원 중 이동하지 않기 위한 제한이다.
- 백업·이전 데이터·실패 staging은 디스크를 추가 사용한다. 자동 정리 없음. Windows/USB/네트워크 드라이브/장편 영상/실제 디스크 고갈/전원 차단은 미검증.

## 검증

Node: 해시·경로/링크 거부·손상·기존 데이터 보관·시작 실패 rollback·복구 기록 유지/시작 차단·중복 작업/취소/강제 종료 거부. Electron E2E: OS dialog만 대역으로 바꾸고 실제 API 종료, 파일 H2 백업, 프로필 변경 후 복원 및 사진/갤러리 유지 검증. 결과는 development-plan에 기록한다.
