# 002. 대표 사진의 로컬 저장

이번 단계는 대표 사진 한 장과 생년월일·출생지 입력이다. 갤러리·연락처·SNS는 아직 포함하지 않는다.

대표 사진 한 장은 H2 파일 DB의 BLOB으로 저장한다. 별도 이미지 파일과 DB 참조를 동시에 변경하는 대신 한 트랜잭션에서 사진 데이터와 프로필 version을 변경한다. 교체나 삭제가 롤백되면 기존 사진도 유지된다. 사용자가 선택한 원본 파일은 읽기만 하며 이동·삭제하지 않는다.

입력은 JPEG/PNG, 최대 5MiB다. 초기 800만 화소 제한은 자동 축소로 대체했다(`005-image-auto-resize.md`). 파일명이나 Content-Type만 믿지 않고 이미지 디코더로 형식과 크기를 확인한다. PNG로 재인코딩하여 업로드한 원본 바이트를 직접 제공하지 않는다. EXIF 등 원본 메타데이터는 유지하지 않으며 EXIF 회전 보정은 아직 지원하지 않는다. 이미지가 회전돼 보이면 사용자가 회전 보정 후 저장한 파일을 선택해야 한다.

일반 브라우저에서는 접근 토큰이 없어 이미지 API도 읽을 수 없다. 사진 변경은 version 조건을 적용해 오래된 화면이 최신 사진을 덮어쓰지 않게 한다. 사진 작업 전 텍스트 변경 저장을 요구하고 작업 중 입력을 잠근다. 네트워크 응답이 유실되면 실제 저장 여부가 불확실할 수 있으므로 다시 읽기로 확인한다.

트레이드오프: PNG 재인코딩으로 파일 크기가 늘 수 있고, 잦은 교체 시 DB 파일 크기가 즉시 줄어들지 않을 수 있다. 이 방식은 제한된 대표 사진 한 장을 위한 선택이며 갤러리·영상 전체 저장 정책이 아니다. 대용량 영상에는 별도 파일 저장과 작업 상태 관리가 필요하다. DB 백업 기능과 저장 공간 정리는 후속 작업이다.
