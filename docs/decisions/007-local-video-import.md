# 원본 영상 선택·저장·작품 연결 (2026-09-28)

## 범위

기존 작품 편집 화면의 원본 영상 영역에서 MP4/MOV 한 개를 선택 또는 드롭한다. 저장된 작품에만 연결하며 작품 정보에 미저장 변경이 있으면 먼저 저장하도록 안내한다. 트레일러, FFmpeg/ffprobe, 인코딩, 재생은 포함하지 않는다.

## 파일과 DB

- HTML File 입력 + 인증된 loopback API로 전송. renderer에 Node/임의 경로 읽기 IPC를 추가하지 않는다.
- `POST /api/filmography/{id}/video?version=...&name=...`, raw `application/octet-stream`. 사진용 multipart 5MB 설정은 그대로 유지한다.
- 최대 2GiB. 확장자 및 선두 `ftyp` 컨테이너 식별만 확인한다. 실제 영상 트랙/코덱/재생 가능성 검증이 아니며, 구형 MOV 등 선두 ftyp가 없는 파일은 현재 거부한다. 다음 인코딩 단계에서 ffprobe 검증 필요.
- 128KiB 버퍼로 스트리밍 복사. 파일 전체를 byte[]/DB BLOB으로 올리지 않는다. 크기 사전 검사/실제 바이트 수 일치 검사/남은 디스크 공간 사전 검사. 실제 쓰기 실패도 별도 처리한다.
- 저장 위치: 앱 data 폴더의 `media/videos/{서버 UUID}.part` → fsync → 같은 폴더에서 atomic move → `{UUID}.source`.
- 사용자 파일 이름은 표시용으로만 DB 저장한다. 경로로 사용하지 않고 경로 구분자/제어문자/200자 초과를 거부한다.
- V7 `local_video`: UUID, 연결 작품 ID, 원래 파일명, 바이트 수, 상태, 생성 시각. READY는 **복사 완료**이며 인코딩 완료가 아니다.
- 복사 중 DB 트랜잭션/연결을 점유하지 않는다. 한 번에 하나만 복사하며 최종 짧은 트랜잭션에서 공통 filmography version을 다시 확인하고 이전 영상 연결 해제 + 새 영상 연결 + version 증가를 함께 커밋한다.
- 작품 삭제는 FK `ON DELETE SET NULL`로 연결만 해제한다. 메타데이터 수정/순서 변경은 기존 영상 연결에 영향을 주지 않는다.

## 실패와 복구

- 복사 중 실패/버전 충돌이면 기존 연결을 유지한다. 새 파일은 FAILED로 남겨 복구 가능성을 보존한다.
- 앱 시작 시 COPYING 기록을 INTERRUPTED로 표시한다. 불완전 복사본을 자동으로 작품에 연결하지 않는다. 자동 이어받기는 없으며 사용자가 원본을 다시 선택한다.
- 파일 복사 완료 후 DB 연결 전에 종료되면 미연결 파일이 남는다. DB 커밋 후 응답만 유실된 경우에는 다시 읽기로 연결 상태를 확인한다. UI는 결과가 불명확하면 변경을 막고 다시 읽기를 안내한다.
- 조회 시 연결된 파일 존재 및 크기를 검사한다. 누락/크기 불일치는 UI에서 재선택 안내. 같은 크기 파일 변조 검출이나 전원 차단의 완전한 내구성은 보장하지 않는다.
- 연결 해제/교체/작품 삭제 후 복사본 및 실패·중단 파일은 **자동 삭제하지 않는다**. 기존 원본과 복사본 손실을 피하기 위한 초기 정책이다. 반복 교체/실패 시 디스크 사용량이 늘며 파일 정리/복원 UI는 후속 작업이다. 사용 중 DB/미디어 폴더를 직접 지우지 않는다.
- ATOMIC_MOVE 미지원 파일시스템은 성공으로 가장하지 않고 오류 반환. macOS/Windows 일반 로컬 디스크를 대상으로 하며 Windows 검증은 별도 필요.

## 검증

임시 파일 H2 테스트: 바이트 일치·원본 보존·재시작·메타데이터 편집 시 보존·교체·연결 해제·작품 삭제·잘못된 형식/이름/길이/크기·읽기 실패·복사 도중 version 충돌·시작 시 미완료 상태 정리·파일 누락 표시.

Electron에서는 7MiB 컨테이너 헤더 fixture를 파일 입력에 넣어 raw 업로드 경로를 검증한다. 이는 재생 가능한 실제 영상 검증이 아니다. 대용량 2GB, 실제 OS 파일 선택 창/드롭, Windows 및 실제 디스크 부족 검증은 별도 필요하다.
