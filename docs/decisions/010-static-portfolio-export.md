# 읽기 전용 공개본 내보내기 (2026-09-29)

## 범위

호스팅 업체를 선택하거나 인터넷에 게시하지 않는다. 현재 저장 상태를 정적 HTML/JS/CSS/JSON/이미지/HLS 파일 묶음으로 만든다. 프로필 편집 메뉴의 **공개본 만들기 · 미리보기**에서 공개 정보 포함을 확인한 뒤 실행한다. 기존 OnFilm 프로필/작품/사진 배치와 재생 화면을 재사용하되 편집 UI/API 의존성을 제외한다.

- 포함: 이름, 소개, 생년월일, 출생지, SNS, 태그, 대표 사진, 갤러리, 작품 정보/섬네일, 연결된 완료 HLS.
- 제외: DB, 버전, 내부 사용자/작품/영상 UUID, 원본 이름/경로/영상, 토큰, 인코딩 기록, 미연결 파일.
- 정적 데이터는 `portfolio.json`에 공개 전용 필드만 기록. 작품은 `film-0`처럼 공개본 안의 식별자를 새로 사용한다. 사용자 문자열은 script/HTML에 삽입하지 않고 JSON에서 읽어 textContent로 표시한다.
- Contact는 이메일만 사용한다. 저장된 이메일이 있으면 이전 public_email 플래그와 관계없이 새 공개본에 포함하고, 없으면 CONTACT ME 전체를 숨긴다. 전화번호/공개 플래그는 API와 공개 JSON/ZIP에 포함하지 않는다. 기존 DB 컬럼은 데이터 보존을 위해 남겨 두며 새 입력/변경에 사용하지 않는다. 이메일을 지워도 이미 만들어진 공개본/ZIP/게시물은 자동 갱신하지 않으므로 새 공개본으로 교체하거나 기존 게시물을 내려야 한다.

## 저장/실패 처리

```
<앱 데이터>/exports/
  <UUID>.partial/site/    생성 도중 또는 중단/실패한 파일 (미공개)
  <UUID>/
    result.json          로컬 완료 기록·파일 목록·총 byte
    site/                호스팅에 올릴 결과물
      index.html
      portfolio.json
      video-player.html
      css/ icons/ images/ vendor/ media/
```

- 단일 생성만 허용. HTTP 요청 중 복사하되 UI에서 진행 중임을 표시하고 이탈 경고를 둔다. 세부 퍼센트와 취소는 아직 없다.
- REPEATABLE_READ 읽기 트랜잭션에서 메타데이터/이미지와 완료 HLS 경로를 확인. 큰 영상 복사는 트랜잭션 밖에서 수행.
- 연결된 영상의 변환이 안 끝났거나 manifest/segment가 없으면 전체 실패. 일부 영상만 조용히 빼지 않는다. 생성된 manifest의 파일명만 허용하고 외부 URI 참조를 거부한다.
- HLS 예상 크기와 여유 공간 확인, 파일별 크기 확인, 완료 목록 기록 후 같은 파일시스템의 atomic directory move로 완료한다. atomic move 미지원 파일시스템은 완료 처리하지 않는다.
- 매번 새 UUID 폴더를 사용하므로 이전 완성본과 편집 DB/원본을 덮어쓰지 않는다. 실패/종료 시 `.partial`은 보관하지만 목록/미리보기로 제공하지 않는다. 자동 청소 없음; 디스크 누적에 주의.
- 응답이 유실됐을 때 결과 다시 읽기로 완료 기록을 확인한다. 재시도는 새 공개본 생성이며 중복 저장을 자동 병합하지 않는다.
- 완료 기록은 재시작 후에도 디스크에서 다시 읽는다. DB 마이그레이션 없음.

## 로컬 미리보기와 독립성

- 로컬 `/api/exports/{id}/site/...`는 기존 실행 토큰/Host/Origin 검사를 유지한다. UUID·완료 목록·경로/심볼릭 링크를 검사하며 site 내부의 등록 파일만 제공한다.
- 로컬 index 응답에만 **로컬 미리보기 종료** 링크를 추가한다. 디스크의 공개 HTML에는 이 링크를 넣지 않는다.
- 결과물의 리소스/재생 링크는 상대경로. CDN 없이 HLS.js와 아이콘/라이선스를 함께 포함한다. 프로필 JSON과 정적 HLS를 읽으므로 Spring/Electron 없이 일반 정적 HTTP 서버에서 동작한다.
- HTML 더블클릭(file://)은 fetch/HLS 제한으로 지원하지 않는다. 앱 미리보기 또는 정적 웹 호스팅이 필요하다.
- Electron 미리보기에서는 외부 SNS 이동 차단 정책을 유지한다. 실제 웹에서는 검증된 HTTP(S) SNS를 새 탭으로 열 수 있다.
- 정적 페이지의 자동재생은 브라우저 정책에 따라 막힐 수 있으며 재생 버튼 안내로 대체한다. 앱 미리보기는 기존 자동재생 정책을 사용한다.
- 최종 호스팅은 올바른 MIME(HTML/JS/JSON/PNG/SVG/m3u8/TS)과 HTTPS 제공이 필요하다. 비용/업체 선정은 실제 파일 수·총 크기 확인 후 별도 결정.

## ZIP 저장·폴더 열기

- 완료된 공개본에 **ZIP 저장**, **결과 폴더 열기** 버튼을 제공한다. ZIP에는 `site/` 내부 파일만 루트 상대 경로로 포함하며 `result.json`, DB, 원본 영상은 포함하지 않는다.
- 서버는 ZIP 전체를 먼저 생성하고 완료한 뒤 전송한다. `<UUID>/portfolio.zip`으로 캐시하므로 공개본 외에 ZIP만큼 추가 디스크 공간이 필요하다. 캐시/이전 공개본 자동 삭제는 하지 않는다.
- Electron main만 OS 저장 창과 폴더 열기를 실행한다. renderer는 UUID만 전달하며 경로나 명령어를 전달할 수 없다. 같은 창의 main frame·정확한 origin·`/export.html` 발신만 허용한다. 완료 기록과 실제 폴더/심볼릭 링크를 검사한다.
- 저장 취소는 파일을 만들지 않는다. 목적지와 같은 폴더의 임시 파일에 스트리밍하고 길이 확인·fsync 후 hard link로 완성 파일을 게시한다. 기존 파일 및 저장 도중 다른 프로세스가 만든 동명 파일을 덮어쓰지 않는다.
- 실패/창 종료 시 진행 중인 다운로드를 중단하고 이번 작업의 임시 파일을 정리한다. 강제 종료/전원 차단은 임시 파일이 남을 수 있다. 백엔드 ZIP 생성은 다운로드 취소와 별개로 완료될 수 있다.
- hard link 미지원 파일시스템(일부 USB/네트워크 저장소)은 저장 실패 안내를 표시한다. 내부 디스크에 저장한 후 복사할 수 있다. 대용량·디스크 고갈·Windows 실기기 테스트는 남아 있다.
- 폴더 열기는 공개용 `site` 디렉터리를 Finder/탐색기로 연다. HTML 더블클릭이 아닌 앱 미리보기로 재생을 확인해야 한다.

## 저장 공간 확인·완료 공개본 정리

- Electron 공개본 화면에서 DB·미디어·공개본 폴더의 파일 크기를 합산한다. 공개본 내부 ZIP 캐시/부분 파일은 포함하지만 외부 백업·복원 전 보관 폴더·외부 ZIP·OS 휴지통은 제외한다. 디스크 할당 크기/여유 공간과 다른 논리적 크기이며, 작업 중 값은 바뀔 수 있다. 심볼릭 링크를 따라가지 않는다.
- 완료 공개본 UUID만 IPC로 받아 실제 경로·완료 기록·등록 파일 여부를 검사한다. 사용자 확인 후 재검사하고 `shell.trashItem`으로 해당 공개본 폴더와 내부 ZIP 캐시를 이동한다. 알 수 없는 파일이나 심볼릭 링크가 있으면 거부한다.
- OS 이동 실패 시 영구 삭제로 대체하지 않는다. 휴지통을 비우기 전 OS에서 복구할 수 있으며 여유 공간 확보에는 휴지통 비우기가 필요할 수 있다. 앱 내부 복구 UI는 없다.
- 원본 DB·사진·영상·백업·외부 ZIP·게시된 사이트는 변경하지 않는다. `.partial` 공개본과 원본/인코딩 미디어 정리는 지원하지 않는다. 이전 공개본 자동 삭제도 하지 않는다.
- OS 휴지통과 확인 창은 테스트에서 임시 폴더 이동/응답 대역으로 검증하며 실제 macOS/Windows OS 조작은 별도 수동 검증 대상이다.

## 검증/남은 작업

- 임시 파일 H2 테스트: 공개 필드 분리, HTML 주입 방지 방식, 상대 경로/아이콘, 결과물 byte 합계, 재시작 유지, 원본 편집 후 기존 공개본 불변, 미완료 영상 거부, 실패 후 이전 완성본 보존, 경로 탈출/완료 기록 노출 차단.
- Electron: 동의 체크/생성/목록/로컬 미리보기. 별도 인증 없는 임시 정적 서버와 독립 BrowserWindow에서 프로필/HLS 재생 및 돌아가기 검증. 자세한 실행 결과는 development-plan에 기록.
- ZIP 엔트리/내용 일치·실패 시 미완성 ZIP 미게시, IPC 발신 제한·취소·기존 파일/경합 보호·끊긴 전송 정리를 자동 검증한다. Electron E2E에서 OS dialog/shell만 대역으로 치환하고 실제 ZIP API와 IPC를 실행한다. 실제 저장 대화상자/Finder 조작은 수동 확인이 필요하다.
- 연락처 외 공개 항목별 선택, 실패 파일 정리, 긴 영상/디스크 고갈/강제 종료 실험, Windows, 실제 호스팅·같은 링크 업데이트는 미구현 또는 미검증.
