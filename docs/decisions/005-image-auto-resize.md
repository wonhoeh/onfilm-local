# 005. 사진을 거부하지 않고 자동 축소

사용자가 픽셀 수를 확인하거나 직접 리사이즈하지 않도록 기존 800만 화소 거부 정책을 변경한다.

- 신규 업로드는 긴 변 최대 2,048px, 종횡비 유지, 작은 사진 확대 없음.
- 예: 4032×3024 → 2048×1536, 3024×4032 → 1536×2048.
- 공통 ImageNormalizer를 대표 사진/갤러리에 적용. 원본 파일·기존 DB 사진은 변경하지 않는다.
- PNG 투명도 유지, PNG 출력과 기존 BLOB 저장/API 형식 유지. DB 스키마 변경 없음.
- 압축 파일 제한은 기존과 같은 5MiB. JPEG/PNG 지원, HEIC/WebP 및 EXIF 회전 자동 보정은 아직 미지원.

## 메모리와 안전장치

원본을 무조건 전체 디코딩하지 않는다. 헤더로 크기를 확인한 뒤 ImageReadParam의 source subsampling을 적용해 중간 이미지의 긴 변을 최대 4,095px 이하로 읽고, 최종 비율/크기로 보간한다. JPEG/PNG 디코더의 내부 버퍼까지 정확한 메모리 상한을 보장하는 것은 아니므로 압축 크기·원본 차원 제한도 유지한다.

정상적인 고해상도 사진은 축소하지만, 원본 한 변 30,000px 초과 또는 2억 픽셀 초과는 비정상/과도한 입력 방어로 거부한다. 한 프로세스에서 이미지 변환은 한 번에 하나만 허용하며 이미 처리 중이면 429로 안내한다. 여러 파일을 선택한 정상 UI 요청은 순차 처리된다.

## 실패 안내

빈 파일, 용량 초과, 미지원 형식, 손상/변환 실패, 안전 범위 초과, 처리 중을 각각 코드/안전한 한국어 메시지로 응답한다. Multipart 제한 단계의 413도 용량 안내로 응답한다. 그 외 서버 오류는 형식 문제로 단정하지 않고 HTTP 상태와 다시 읽기 안내를 표시한다.

기존 사진의 일괄 재인코딩·원본 덮어쓰기·DB 정리는 수행하지 않는다.
